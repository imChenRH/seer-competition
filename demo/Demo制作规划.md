#### 4.1.2 需要的3D资产
| 资产 | 来源 | 备注 |
|------|------|------|
| 集装箱 | Isaac Sim SimReady资产库 | 标准20尺/40尺集装箱 |
| 月台 | SimReady工厂资产或自建 | 与集装箱地板齐平 |
| 栈板货物 | SimReady Pallet_A1 + Cardbox 系列（HF: nvidia/PhysicalAI-SimReady-Warehouse-01） | 官方 PBR 资产，厘米单位需缩放 0.01 |
| 叉车 | 开源USD模型或简化自建 | 差速底盘+门架+货叉，约5个关节；缺项可向仙工协调（会议承诺） |
| 传送带 | SimReady工厂资产 | 简单静态模型即可 |
| 地面/光照 | Isaac Sim自带 | 集装箱内偏暗，须在场景内补光源；否则 RGB-D 深度噪声大，影响栈板识别 |

#### 4.1.3 叉车模型关节定义
| 关节 | 类型 | 范围 | 说明 |
|------|------|------|------|
| wheel_left / wheel_right | 转动关节 | 连续 | 差速驱动 |
| mast_lift | 平移关节 | 0~3m | 门架升降 |
| fork_tilt | 转动关节 | -5°~+10° | 货叉倾斜 |
| fork_side_shift | 平移关节 | ±100mm | 货叉侧移（可选） |

动作空间（5维，无夹爪——叉车货叉没有"夹紧/释放"，叉取 = 货叉插入栈板孔 + 门架起升）：
```python
action = [
    linear_velocity,   # 前进/后退速度 m/s, [-1.5, 1.5]
    angular_velocity,  # 转向角速度 rad/s, [-0.8, 0.8]
    mast_height,       # 门架目标高度 m, [0, 3.0]
    fork_tilt,         # 货叉倾斜角 rad, [-0.087, 0.174]
    fork_side_shift,   # 侧移量 m, [-0.1, 0.1]
]
```
> 注：差速底盘 + 门架/货叉构型与仙工 SFL 系列 AGV 叉车一致（非机械臂式夹爪）。
> 叉取动作采用简化实现：货叉对准栈板底部平面 → 接触传感器触发 → 门架起升（不追求物理插孔，绕开 PhysX 刚体插孔碰撞坑）。

#### 4.1.4 传感器配置
| 传感器 | 安装位置 | 话题 | 频率 | 用途 |
|--------|---------|------|------|------|
| RGB-D相机 | 叉车前部，门架上方 | /camera/rgb, /camera/depth | 15Hz | Fast-WAM视觉输入 |
| 2D激光雷达 | 叉车前部 | /scan | 10Hz | 避障、集装箱壁检测 |
| IMU | 叉车底盘 | /imu/data | 50Hz | 姿态估计 |
| 关节编码器 | 各关节 | /joint_states | 60Hz | 本体状态反馈 |
| 接触传感器 | 货叉尖端 | /fork/contact | 事件触发 | 判断是否叉到栈板 |

#### 4.1.5 ROS 2话题清单
**Isaac Sim发布（仿真→外部）：**
- /camera/rgb（sensor_msgs/Image）
- /camera/depth（sensor_msgs/Image）
- /camera/camera_info（sensor_msgs/CameraInfo）
- /scan（sensor_msgs/LaserScan）
- /imu/data（sensor_msgs/Imu）
- /joint_states（sensor_msgs/JointState）
- /odom（nav_msgs/Odometry）
- /fork/contact（std_msgs/Bool）
- /tf（tf2_msgs/TFMessage）

**Isaac Sim订阅（外部→仿真）：**
- /forklift/cmd_vel（geometry_msgs/Twist）— 底盘速度
- /forklift/mast_cmd（std_msgs/Float64）— 门架高度
- /forklift/fork_cmd（forklift_msgs/ForkCommand）— 货叉控制
- /task/start（std_msgs/String）— 开始任务
- /task/abort（std_msgs/Bool）— 紧急停止

> 频率说明：产品规格中底层控制为 100Hz；Demo 仿真中 Isaac Sim PhysX 物理与规控脚本统一为 60Hz（控制/物理同频，避免频率不匹配）。传感器频率（15/10/50/60Hz）低于控制频率是真实系统常态——传感器与控制解耦，控制按固定周期执行。

### 4.2 Fast-WAM推理展示

#### 4.2.1 技术验证部分（真跑）
在AutoDL服务器上：
```bash
# 1. 安装LeRobot（源码安装）+ Fast-WAM 依赖
git clone https://github.com/huggingface/lerobot && cd lerobot
pip install -e ".[fastwam]"          # 仅推理
pip install -e ".[fastwam,libero]"   # 含 LIBERO 评估环境

# 2. 加载预训练权重，在LIBERO环境跑推理（官方镜像 lerobot/fastwam_libero_uncond_2cam224）
lerobot-eval \
  --policy.path=lerobot/fastwam_libero_uncond_2cam224 \
  --policy.device=cuda \
  --env.type=libero \
  --env.task=libero_spatial \
  --eval.n_episodes=10
```
- 录屏展示：LIBERO环境中机械臂根据指令完成操作
- 标注：Fast-WAM推理延迟 ~190ms（论文实测；对照 Joint 580ms / IDM 810ms）；LIBERO 全任务成功率 97.6%（Spatial 98.2 / Object 100.0 / Goal 97.0 / Long 95.2，来源：LeRobot README / arXiv:2603.16666）
- 目的：证明"Fast-WAM不是PPT，真的能跑"

> ⚠️ 已知复现风险（独立复现报告：Allen AI vla-evaluation-harness）：该 checkpoint 存在加载缺陷（tokenizer_model_id 内嵌本地路径，需覆写），独立复现未达标。应对：
> 1. D1 先做 24h 技术验证：加载权重 → 跑 1 个 LIBERO 任务 → 确认有动作输出
> 2. 失败则切离线推理演示：在录制视频帧上逐帧跑 Fast-WAM 推理（推理只需第一帧 latent + 动作去噪，离线天然可行），展示真实动作输出
> 3. 修复 tokenizer 路径后回归真跑

#### 4.2.2 叉车场景部分（影子模式 + 架构展示）
叉车控制由规控脚本执行（阶段1真实路线），Fast-WAM 以**影子模式**按需推理，面板同时展示两条通道：
- 执行通道（高亮）：规控脚本实际输出的动作
- 建议通道（并行）：Fast-WAM 输出的动作建议，标注"阶段1影子验证 → 阶段2微调后接管"

**稀疏调用原则（对齐 Harness VLA 实证：解析原语占调用 84.2%）**：Fast-WAM 建议通道**仅在接触丰富技能启动时出现**（FORK-OP-01 货叉插入 / FORK-OP-02 门架起升 / FORK-OP-03 倾斜 / FORK-OP-04 放置 / FORK-OP-05 对接）；导航/感知/运输类技能（FORK-NAV-* / FORK-PER-* / FORK-INT-*）不出现建议通道——导航与运输由规控承担，接触丰富阶段才是模型接管的候选。同时省显存（不做连续闭环推理）。

> 真实性标注：Fast-WAM 仅在 LIBERO 双臂场景训练过，叉车场景下建议通道为**架构示意**（展示输入输出形态）；真推理仅限 4.2.1 LIBERO 技术验证。不宣称 WAM 参与叉车实控。

  - 语言指令："叉取偏移的栈板"

### 4.3 规控脚本（阶段1真实控制）

用Python写叉车控制状态机，通过ROS 2控制Isaac Sim中的叉车：

```
状态机：
IDLE → ENTER_CONTAINER（导航进入集装箱）
     → APPROACH_PALLET（对准栈板，视觉识别位姿）
     → INSERT_FORKS（货叉插入栈板孔）
     → LIFT_PALLET（起升栈板）
     → EXIT_CONTAINER（驶出集装箱）
     → NAV_TO_CONVEYOR（导航到传送带）
     → PLACE_PALLET（放置栈板）
     → RETURN（返回待命点）
     → DONE
```

异常分支：
- 栈板偏移 > 阈值 → 重新对准（最多3次）
- 视觉识别失败 → 等待/重试/请求人工
- 激光雷达检测障碍 → 停车/绕行
- 接触传感器异常 → 停止并告警

技术实现：
- 导航：简单的路径跟踪（waypoint + Pure Pursuit）
- 栈板对位：从深度图提取栈板孔位，计算偏差，PD控制对准
- 门架/货叉：位置控制
- 叉取：简化实现——对准栈板底部平面 + 接触传感器触发 + 门架起升（见4.1.3注，不追求真实插孔）
- 安全验证（Demo 简化口径）：关节限位=运动学验证；激光雷达最近点距离<0.5m→减速/停车=碰撞检测；月台区虚拟安全边界=人机距离。面板展示完整三层，旁白注明"Demo 为简化验证，生产级完整三层"
- 不需要复杂SLAM，场景固定，用预设路径+视觉微调

### 4.4 Aily 上层 AgentOS（飞书侧）

#### 4.4.1 智能体配置
- 名称：AgentOS智能调度员（Aily 自定义智能体）
- 平台：飞书 aily（aily.feishu.cn），飞书官方智能体平台
- 能力：对话决策（任务分解/Fallback判断）+ 多维表格工具（创建/新增/批量添加/查询）+ 发送飞书消息（告警）
- 工具：飞书多维表格（关联 Base）、发送飞书消息；可选 Webhook 告警工作流（由桥接脚本触发）
- 人设提示词：见 `demo/Aily_AgentOS提示词.md`（5张表 + 13技能 + 10Fallback + 3剧本）

#### 4.4.2 工作流
1. **理解与任务分解**：接收自然语言指令 → 从技能库表选技能组成序列 → 生成任务ID → 计算时间预算（Σ正常耗时）→ 创建任务记录 → 写审计日志
2. **执行推进（按执行来源分流）**：任务创建时写死"执行来源"，全程不变——一个任务只有一个推进者
   - 执行来源=sim（真实仿真）：以任务表"外部执行状态"回写为准，**不自行推进**；异常事件来自外部（桥接脚本回写或 Webhook 触发）→ 查Fallback表决策 → 严重异常发告警消息 → 写审计
   - 执行来源=simulate（模拟）：按剧本/正常耗时**对话逐步推进**（每完成一个技能回复一条进度消息），更新状态、写审计；异常按剧本注入
3. **任务完成**：更新状态 → 更新叉车状态统计 → 写审计日志 → 按固定格式回复操作员

#### 4.4.3 与Isaac Sim的联动（桥接脚本，双模式已验证）
> ✅ 真实模式已实现：桥接 SIMULATE=0 调用 execute_task.py 驱动 Isaac Sim 执行，逐技能回写（T-801 端到端验证通过）
- Aily 通过飞书多表读写任务/审计/状态，**不直接碰 ROS 2**
- 桥接脚本（Python，运行于 AutoDL）：经飞书开放平台 API 轮询任务表 → 发现"执行来源=sim"的新任务即通过 ROS 2 发布 /task/start 给 Isaac Sim
- Isaac Sim 执行结果经 ROS 2 回传 → 桥接脚本回写任务表"外部执行状态"与异常事件；异常时调用 Aily Webhook 触发告警工作流
- 简化方案：演示时桥接脚本可改为自动模拟状态更新——此时任务"执行来源=simulate"，Aily 对话逐步推进（飞书线独立可录）

## 十、关键决策记录

1. **仿真平台**：Isaac Sim + OpenUSD（沈博指定），非Web 2D
2. **中层模型**：Fast-WAM（沈博认可WAM方向，190ms适合端侧）
3. **叉车控制**：阶段1用规控脚本（沈博建议"先跑通产线"），Fast-WAM定位阶段2
4. **Demo不真训练叉车模型**：5天内数据采集+训练+验证不可行，展示技术验证+架构+路线图
5. **上层用飞书**：Aily+多表真实运行，满足比赛飞书AI能力要求
6. **云GPU**：AutoDL RTX 4090，按小时租，不用时关机
7. **Demo 采用影子模式呈现**：Fast-WAM 与规控脚本并行展示"建议 vs 执行"，不夸大模型当前能力；LIBERO 真推理仅作技术可行性证据
8. **飞书侧用 Aily 主载**：aily 自定义智能体（对话决策 + 多维表格工具 + 消息告警 + Webhook 告警工作流），飞书官方 AI 平台叙事最硬；OpenClaw/豆包办公模式降级备用
9. **叉取动作用简化实现**：货叉对准栈板底部 + 接触检测 + 门架起升（不追求真实插孔），绕开 PhysX 刚体插孔碰撞坑
10. **自由展示区定位**：Demo 视频装不下的方案优越性 + 进阶目标（Transformer+规控采集数据→微调 Fast-WAM）；材料复用 5 篇补充材料，内容到时细化
11. **进度单一推进者原则**：任务创建时写死"执行来源"（sim/simulate）——sim 由桥接脚本回写推进、Aily 只读表汇报/审计/Fallback 决策；simulate 由 Aily 对话逐步推进。一个任务只有一个推进者，杜绝双轮询竞态
12. **架构同构论据**：Harness VLA（清华等，arXiv:2607.08448）证明"LLM 规划器 + 固定原语库 + 冻结 VLA 局部专家"在扰动基准上优于端到端 38.6pp（解析原语占调用 84.2%）——我们的 Aily+技能库+Fast-WAM+规控与其同构，阶段1 规控为主不是妥协而是实证最优分工；Fast-WAM 建议仅在接触丰富技能（FORK-OP-*）出现
