# 当前 Demo 严格审计（2026-08-13）

## 结论

审计时的仓库成果更接近“概念和管线原型”，尚不是可复现、可向企业证明闭环的 Demo。选择局部重构：保留业务模型、飞书表、远端环境、Fast-WAM 模型和资产；重做执行、证据、桥接和控制台。

## 证据与问题

### P0：仓库不能复现核心闭环

审计时仓库没有 `execute_task.py`、场景构建脚本、控制器、桥接真实模式、USD、依赖文件或测试。核心文件只存在 AutoDL，其他成员无法从 Git 复现。

### P0：所谓“真实执行”是动画 Xform，不是已声明的控制器

远端旧 `execute_task.py` 直接调用 `SetTranslate` 移动 `/World/Forklift/chassis` 和 `carrier`；文件自身也写明“动画级别，物理关节版本后续替换”。它没有导入或调用 `controller/forklift_controller.py`。旧控制器非虚拟模式的驱动、门架、感知、接触和障碍分支全部仍为占位。

### P0：一个九技能任务被完整执行九次

旧桥接在 `for skill in skills` 循环内部启动完整 `execute_task.py <九技能序列>`。T-801 的 `bridge.log` 中九个 `SKILL_DONE` 序列重复出现九组，再被写为完成。这不是单任务单执行闭环。

### P0：现有录屏不能证明目标任务

- 旧 `phys_mast.mp4` 只有约 0.05 秒/一帧，不能证明“300 帧真实关节驱动”。该无效素材已在 2026-08-15 清理时移除，历史提交仍保留。
- 三幕视频主要是空灰场景、栈板/方块和画面位移；看不清完整进箱、叉取、载荷起升、转运、放置、恢复和人工介入。
- 旧场景把 Y 当作高度，而 Isaac Sim 正式坐标约定为 Z-up；叉车子部件又混用了世界坐标和局部坐标，造成错位和遮挡。

### P1：旧网页是演示动画，不是运行控制台

`architecture_panel.html` 的技能完成、Fallback、成功率、190 ms 和“真实控制”均由浏览器 `setTimeout` 与常量生成，没有读取飞书、Isaac、日志或 API。它只能作为视觉草图。

### P1：Fast-WAM 口径混淆

远端日志证明模型能加载并输出 `[1, 7]` 动作，单次首次推理为 0.86 秒；同时存在 tokenizer/加载告警。190 ms 是论文指标，不是本机实测。Fast-WAM 没有控制当前叉车，也没有叉车后训练数据。

### P1：记录互相矛盾

同一份《进度记录》先称真实桥接和控制闭环完成，末尾快照又写“规控待接仿真、真实模式待接”；《待办事项》仍把已声称完成的场景、面板、录制列为进行中。

## 已采取的重构方向

1. 单一事件契约与连续 JSONL，任务真相不再由页面或飞书状态文字决定。
2. normal/recovery/intervention 三场景共享同一状态机，终态分别严格校验。
3. 桥接先认领任务，只启动一次 runner；整份事件校验后才幂等回写。
4. Isaac 场景改为 Z-up、局部子部件和显式载荷耦合；画面采用剖视箱体便于审计。
5. 网页只读 JSONL/视频，删除固定成功率和假推理延迟。
