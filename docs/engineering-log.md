## 被推翻的结论（审计发现）

这次审计把此前的"已完成"逐条证伪，是本项目的转折点。当时认定的**关键问题**：

**P0 — 所谓"真实执行"是动画，不是控制器。**
旧 `execute_task.py` 直接调用 `SetTranslate` 移动底盘和载荷，文件自身也写明"动画级别，物理关节版本后续替换"；它从未导入或调用控制器模块。所谓"控制器非虚拟模式"的驱动、门架、感知、接触分支全部是占位。

**P0 — 一个九技能任务被执行了九次。**
旧桥接在 `for skill in skills` 循环**内部**启动完整的九技能 runner。运行日志中九组 `SKILL_DONE` 序列重复出现九次，却被写成一次完成。

**P0 — 核心闭环无法从仓库复现。**
执行脚本、场景构建、控制器、桥接真实模式、USD、依赖文件、测试全部只存在于远端服务器，其他协作者无法从 Git 复现任何东西。

**P0 — 录屏不能证明目标任务。**
三幕视频主要是空灰场景与画面位移，看不清进箱、叉取、载荷起升、转运、放置、恢复与介入。所谓"300 帧真实关节驱动"的视频实际只有约 0.05 秒一帧。旧场景还把 Y 轴当高度，与 Isaac Sim 的 Z-up 约定冲突。

**P1 — 网页是演示动画，不是运行控制台。**
技能完成、Fallback、成功率、190 ms 延迟全部由浏览器 `setTimeout` 与常量生成，没有读取任何日志或 API。它只能作为视觉草图。

**P1 — 口径混淆。**
"已实现"、"论文指标"、"规划中"混用；Fast-WAM 的 0.86 s 单次推理与论文的 190 ms 被混写；同一份进度文档前后自相矛盾。

审计评分：**3/10（概念原型）**。其中"工程可复现性"1/10、"证据与口径纪律"2/10。

## 重构决策

审计后选择**局部重构而非推倒重来**——保留业务场景、九技能与 Fallback 设计、飞书表、远端环境与 Fast-WAM 独立验证结果；重做执行、证据、桥接与控制台。

| 决策 | 理由 |
|---|---|
| 单一 JSONL 事件契约取代分散状态口径 | 页面、飞书、日志各自宣布成功是矛盾的根源 |
| 三场景共享同一状态机 | 此前每个场景一套逻辑，无法交叉验证 |
| 桥接"认领一次、执行一次、回放一次" | 直接修复"九次执行"缺陷 |
| 后端不能自己宣布成功 | 成功后置条件必须由可观测谓词判定 |
| 只读控制台，全部数字由证据派生 | 删除硬编码成功率与假延迟 |
| 载荷判定需要几何 + 关节双条件 | 单一几何判定可被轨迹巧合满足 |
| 独立碰撞认证而非依赖 PhysX 静态碰撞 | 单帧位姿插值会穿透，静态 CollisionAPI 不会阻止 |

## 关键工程决策

### 为什么需要独立的碰撞守卫

PhysX 的静态 `CollisionAPI` **不会**阻止单帧位置或偏航插值穿透静态几何。旧路径在传送带侧面产生扫掠重叠，旧栈板目标还低于滚筒顶面约 0.23 m。

因此实现了纯 Python 的 2.5D OBB/SAT 扫掠守卫（`src/seer_demo/isaac/collision.py`），无第三方依赖，可在普通 CPython 下测试：

- 相邻帧按平移 ≤ 0.025 m、偏航 ≤ 0.5° 细分采样；
- 动态集合显式包含车身、四轮、倾斜叉架、双货叉，以及与场景**共用**的 5 根 deck、3 根 runner、4 个 cargo；
- 只允许方向正确、误差 ≤ 1 mm 的支撑面接触；
- 在时间线生成、Isaac 每帧写入、分屏合成、清单生成四处失败关闭。

### 迭代中发现并修正的缺陷

守卫本身也经历过迭代，每次都由独立复核发现：

1. 自由载荷未纳入动态集合 → 补入；
2. 载荷—车身/叉架未检查 → 补入；
3. 场景的实际 4° 货叉倾角与守卫不一致 → 统一；
4. 货叉—Cargo 有 10 mm 穿透 → 修正为 Cargo 抬至 deck 顶面，载荷改为 12 个场景共享部件逐件扫描；
5. V3 中集装箱地板顶面高于世界地面 0.12 m，而轮底在 `z=0`，旧守卫未建模轮胎 → 判定为 Important，**暂停提交并推翻 V3 证据**；
6. V4 引入轮胎支撑接触合同：只允许轮底与齐平地板产生 ≤ 1 mm 的下切面接触；
7. intervention 的两块障碍物由场景与守卫**共享同一组几何定义**，避免视觉几何与认证几何分叉。

### 相机与可见性

构图不是审美问题而是证据问题。相机改为叉车局部坐标下的 13 mm 侧前方动态跟随，按逐帧主体包络拟合，保证完整叉车与近距交互货物解析边距 ≥ 5%，并限制在中央走廊、集装箱后墙前方、顶梁下方。首次实机预览发现横梁遮挡、第二次发现货架货物遮挡，均在正式渲染前失败关闭并修正。

### 视频时钟与事件时钟

**视频帧是唯一权威时钟。** 分屏右栏按 `observed_frame / fps` 投影，不再把事件逻辑时钟 `sim_time_s` 直接当视频秒数；无观测帧的启动事件继承前一观测边界。Isaac 后端的事件时长改从时间线帧时钟派生，使未来重渲染的事件时间与视频一致。这修复了旧证据中右栏比左栏提前约 15 秒显示完成的问题。

### Fast-WAM 的两次纠正

1. **预算纠正**：先用 600 步"语义迁移预算"跑自定义苹果/黄盘任务，掩盖了任务错配。后删除全部自定义资产与 BDDL 覆盖，回到 checkpoint 训练分布内的官方 `libero_goal` task 8 `put_the_bowl_on_the_plate`，恢复官方 300 步预算与原版成功谓词。
2. **显存纠正**：24 GB 显存峰值溢出。改为 CPU 装载后一次性迁移至 CUDA，任务文本上下文预计算后释放编码器。

同时把"目录名自证模型身份"改为运行前核对 Hugging Face revision 并计算实际加载的 config/weights SHA-256。

## 复现性设计

| 机制 | 目的 |
|---|---|
| `.gitattributes` 统一 LF | Manifest 的 SHA-256 由 LF 生成，Windows CRLF 检出会破坏复验 |
| 证据目录不含 `frames/` | 渲染中间帧可再生，不入库 |
| `EventWriter` 用 `open("x")` | 拒绝覆盖既有证据，重试必须使用新 run_id |
| `.runner-complete.json` 收据 | runner 成功后一次写入四产物哈希；重启只能验证并回放，绝不重启 runner |
| 每层重验上级产物 | `validate → summary → video → manifest → server` 逐层不可信输入重新校验 |

## 已知自证边界

诚实记录现有校验的局限，避免把"校验通过"误读为"结论独立成立"：

- `collision_check_count`、`minimum_body_clearance_m` 由被测程序自报，构建器只断言类型与阈值区间，**不做几何独立复算**；
- 事件轨迹校验器与轨迹生成器同源（`contracts.py` 硬编码的期望轨迹正是生成器产出的轨迹），属"被断言符合"而非"被独立推导"；
- `MANIFEST.json` 自身未被哈希、无外部时间锚定，可被整体重写；
- 构建脚本层与 GPU/Isaac 层只有源码字符串级断言，无端到端执行测试；
- 事件时间戳跨度仅数毫秒而仿真时长数十秒，说明证据是**运行结束后确定性回放写入**，不是实时流式记录。
