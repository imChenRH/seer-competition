# SEER Demo 第二轮修正设计

## 结论

采用局部重构。保留现有 JSONL 证据、Manifest、三种 Isaac 运行和 Fast-WAM 独立验证；重写场景路径/姿态契约和网页首屏状态，不推倒已验证的证据服务。

## A. 场景与物理

### 坐标与布局

- 集装箱作为一个整体 Xform，位于仓库作业区并绕 Z 轴旋转 `8°`。
- 输送线与集装箱分离到更远、横向错开的作业区，并绕 Z 轴旋转 `-6°`。
- 月台独立于集装箱和输送线，作为静态碰撞体，避免三者形成一条正对直线。
- 叉车先在安全走廊行驶，再在低速精确接近阶段对齐集装箱；取货后退回安全走廊，再转向输送线，车身不得进入设施碰撞包围区。货叉进入托盘/输送线目标区域属于任务所需接触，不计为车身穿模。

### yaw 与载荷

- `FrameState.yaw_deg` 来自时间线分段，不再恒为 0。
- 集装箱对准阶段平滑旋转至 `8°`，退出后再平滑转向输送线的 `-6°`。
- `apply_frame` 同时写入默认值和时间采样的 `xformOp:rotateXYZ`。
- 载荷附着位置使用 yaw 旋转后的叉车局部偏移，观测函数也用实测 yaw 反算相对位置，避免旋转后误报附着失败。

### 物理角色契约

- 动态/运动学刚体：叉车根节点 `3200kg`、活动载荷根节点 `450kg`。
- 显式约束：活动载荷只在抓取区间通过 `UsdPhysics.FixedJoint` 与叉车连接。
- 静态碰撞体：地面、墙体、货架、集装箱、月台、输送线、背景托盘和障碍物。它们应用 `CollisionAPI`，不应用 `RigidBodyAPI`，因此由 PhysX 作为静态设施处理。
- 非物理可视元素：灯光、车道标线、相机、材质引用。车道标线刻意不加碰撞。
- 代码暴露可机器核验的设施物理清单；测试验证每个关键设施类别均声明静态碰撞角色。

### 真实性边界

叉车仍使用运动学位姿目标，不能宣称 PhysX 求解其行驶碰撞响应。缓解穿模依靠几何包围区、安全走廊、设施错位与姿态时序；真实车型和控制接口到位后再替换为经过标定的车辆模型。

## B. 网页发送门控

### 初始状态

页面主体只显示四个模式按钮和飞书式 AgentOS 对话窗口；证据摘要、视频、技能链、日志、Fast-WAM 详细内容和边界说明全部隐藏。

对话窗口采用飞书式桌面会话语义：左侧应用栏、中间会话标题与消息流、底部输入框及蓝色发送按钮。用户后续补充的 1200×1329 参考图保存为 `demo/agentos对话模版.png`；实现参考其白色会话页、顶部智能体身份栏、回复卡、快捷指令和底部编辑器结构。

### 模式与发送

- 四个按钮是唯一的模式入口；删除 `run-select`。
- 切换模式只更新预填任务和当前会话标签，同时收起之前展开的证据。
- 点击发送后才加载并展示所选模式的内容。
- 正常、恢复、人工介入模式展开对应证据视频和审计数据；Fast-WAM 展开独立验证页。
- 任意输入仍不生成虚假证据：若与该模式记录任务不一致，界面明确提示并回填可审计任务，然后展示真实证据。
- 异步请求沿用 generation 所有权检查，快速切换模式时旧响应不能覆盖新选择。

## 验收

- Python 单元测试覆盖非零 yaw、顺逆时针旋转、旋转后的载荷耦合、设施物理分类、设施错位和路径安全余量。
- Web 静态契约与 JavaScript 行为测试覆盖初始隐藏、唯一模式入口、切换后收起、发送后展开和 Fast-WAM 发送门控。
- 三个 Isaac 场景重新生成，并用正式视频、USDA、JSONL、summary 和 Manifest 替换旧证据。
- 浏览器逐一验收四种模式，确认发送前没有视频，发送后显示正确内容。
